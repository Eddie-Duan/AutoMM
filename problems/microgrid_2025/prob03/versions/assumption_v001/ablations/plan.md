## 1. 适用性判定（必做，不跳过）

本问在 `config/workflow.yaml` 的 `mandatory_stages` 中，**不适用「跳过」，也不允许 `skipped`**。
`ablation` 回答三个问题（`agents/ablation-analyst.md` §团队要求）：

1. 核心结论（交付期/全期 `C_total` 与其分解、`Σq_em`、`Σc`、`Σq_dis`、表 1/2/3）**是否依赖模型族**；
2. 被消融项（跨日携带、完全信息、调整机制、决策时刻密度、LP 松弛、题面/降尺度口径）各自的**经济贡献**；
3. 论文主表**推荐采用的模型及理由**（B0：唯一候选 = `M1`）。

**不激活项的处置**（`agents/ablation-analyst.md` §团队要求）：`M2a` 与 `M1` 算法同构（F6/T8）、`M7·PLAN-EXP`
在确定性口径下退化（T6）——两者都**不**作为「跳过整个阶段」的理由：`M2a` 作为**回归检查**保留并落盘，
`PLAN-EXP` 作为**撤销记录 + 退化证明**保留并在报告中写明依据。

| `M7·PLAN-EXP` | — | — | — | **T6 撤销，不执行**（见 §0.3） |

**C3 与 T7-3 的预注册冲突登记（跑数前写定，不得事后改）**：团队 `B4-C3` 要求链级
`|ΔC(M8, M1)|/C(M1) ≤ 1e-8`。但团队自己的 **T7-3** 审计（`run003/t7_tiebreak.json`）证明
**1024/1460 层**在主目标最优面上**仍有吞吐量多重最优**（`throughput_unique = False`），即 T7-1/T9 的
字典序规则**并不能唯一确定提交点**；`M1` 是「前一日已提交轨迹 → 次日计划层初值」的向前递推（F1），
因此任何落在不同最优面点的独立实现都会经**跨日状态传播**改变链级总费用，量级与 `T7-6` 实测的
`2.2566e-04` 同阶。**本阶段不修改 `C3` 的阈值**：如实报告链级判定；同时新增**补充检查 `C3L`**
（非团队 `C1–C10` 之一，明确标注）——把 `M1` 的提交输入（`e_start`、`plan_b`、支配层预报）喂入独立实现，
**逐层**比较主目标最优值（`≤1e-9`）与残差，以隔离「实现/公式正确性」与「最优面选择非唯一」。
该冲突与 `C3L` 的定位须由团队在 `cross_question_review` 确认。

**档位说明（跑数前冻结）**

- `M5` 的发布集：新增决策时刻**只用最近一次已发布预报**（0/6/12/18，D5-A）；故 A9 的结论限定为
  「**决策频率**」而非「预报信息量」，不得表述为「引入新预报的价值」。
- `M5` 的提交宽度：决策时刻 `t_j` 提交时段 `6t_j+1 … 6t_{j+1}`（相邻决策时刻之间），最后一个提交到 144；
  `M1` 的 `{0,6,12,18}` 在此规则下**逐位退化为 accepted 链**（作为 `M5` 实现的回归检查）。
- `M7·D2-B` 与 `M7·D2-C` 的调整层目标为 `min Σ[−0.5p·u⁺ + 1.5p·u⁻]`（因读法 B 的 `p·min(b,q) = p·b − p·u⁺`
  在调整层是常数项），**必须显式加入由 F8 推导的紧上界** `u⁺ ≤ b`、`u⁻ ≤ q_max = L·Δt + 833.3333 + Π_m·Δt`
  以免负系数导致无界；两条读法的**总费用公式代数恒等**（差值恒为 0），该恒等式作为一条发现登记，
  判据 `C7` 仍要求两条都跑、全量落盘。
- `M6` 的 Big-M **逐时段**由模型推导，禁止放大调参；oracle 只覆盖 4 个指定日（`2025-03-20/06-21/09-23/12-21`）
  的 3 个调整层（计划层无 `u±`，不受线性化影响），全年无损性由引理 L5 承担并**显式登记降级**。
- `M8` 与 `M1` 的 tie-breaking 规则**完全一致**（T7-5）；差异只在书写次序、`s` 消去与求解器设置。

原始样本（`raw_cases.jsonl`）与汇总统计（`comparison.json`/`summary.json`）分开保存。
`code_sha256` 为脚本自算（仅 `*.py`），与 harness `code_hash`（含 `task_config.yaml`/`task_spec.yaml`）

## 6. 失败处理与重跑纪律

- 退出码：`0` 正常；`3` 输入/参数非法；`4` `C1` 基线闸门失败；`5` 墙钟预算耗尽；`1` 未捕获异常。
- 若 task 以 `timed_out`/`interrupted`/非零退出结束：按 `agents/resource-manager.md` 用**新 attempt +
  新 `output_directory`**（如 `..._ablation_run002`）重跑，**不得**覆盖 `..._ablation_run001`，
  并把失败指纹记入 `task_submission.md`。
- `M6` 的 MILP 失败或超时**只**使 `C6` 降级（D6-A 已允许），**不**使整批失败；`M6` 失败不影响 `M1` 主结果。
- 任一 `C1`–`C10` **未通过不得改写判据**：如实登记 `criteria_failed` 与技术债，交 `sanity`/论文原样披露。
- 本动作**不创建 task、不写 `results/`、不运行 365 天正式计算**（implementation/ablation 只做静态检查与
  小型探针）；正式数值一律以隔离 task 的产物为准。

## 7. 与后续阶段的接口

1. `record_optional_stage(stage="ablation", decision="completed", reason=…)` 只在结果就绪、`report.md` 落盘后
   由下一次唤醒的 `ablation-analyst` 动作发出；本动作不预先宣称阶段完成。
2. `question_manifest.conclusion` 三字段在 `ablation` 收尾动作补齐（此前为空会使 `locally_completed` 门禁报错）。
3. `ablation → locally_completed` 是 `config/gates.yaml` 允许的唯一迁移（`ablation` 的 allowed transition 只有
   `locally_completed`）；本阶段因此必须在 `ablation` 内完成「提交 → 执行 → 汇总」三步。
4. 图件**不**调用 `record_figure_review`（团队 B5：ablation/robustness 图件不登记为交付图表）。
5. 论文主表一律以 `run003`（accepted `M1`）为准；本阶段数值只作对比与敏感性，**不得**替换主结果（B0）。
