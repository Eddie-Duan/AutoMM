# AI 工具使用详情

_2026 年高教社杯全国大学生数学建模竞赛 · C 题  微网与外部电网电力调控策略_

本参赛队在竞赛过程中使用了 AI 工具，核心建模与分析由参赛队主导，以下按《全国大学生数学建模竞赛人工智能工具使用规定（2026 年试行）》第 4 条逐项说明。

## 一、所用 AI 工具名称、版本或型号

- **DeepSeek Harness（dsh）**
  - 版本或型号：0.1.1-rc.2（headless profile）
  - 用途：本地 Agent 运行时：按阶段组装提示词、回收结构化响应、驱动工作流状态机
- **DeepSeek 大语言模型**
  - 版本或型号：deepseek-v4-flash-vision-exp
  - 用途：上述各阶段 Agent 的底层生成模型，通过 dsh headless profile 调用
- **GitHub Copilot（VS Code 扩展，本会话模型 DeepSeek V4 Flash）**
  - 版本或型号：随扩展自动更新，未固定版本号
  - 用途：人机结对：环境配置、脚本编写与调试、题面与附件格式解析、终端操作

## 二、具体使用目的和环节

- 题面解析与工作流拆解：划分小问、登记全局符号表、检查小问间依赖
- 文献检索与元数据核验：生成候选文献池并核验题录信息
- 假设显式化：把题面未给出的口径写成可版本化的假设条目并标注依据
- 模型与公式推导辅助：起草目标函数、约束与求解思路，供人工判断取舍
- 求解代码实现与调试：编写与修改求解脚本、排查运行错误
- 计算结果的一致性检查：量纲、边界、约束残差与常识性核对
- 图表生成脚本：绘图样式统一与图形文件产出
- 论文初稿组织与语言润色：按模板组织章节、统一符号与编号、润色行文
- 环境与流程操作：依赖安装、目录整理、命令执行等工程性工作

## 三、主要提示方式与使用过程说明

- 分阶段结构化提示词：每个阶段 Agent 只接收当前阶段的输入清单、约束条件和输出要求，不接触后续阶段的答案
- 强制结构化输出：响应必须是符合 config/agent_response.schema.json 的 JSON，由 harness 校验后才允许改动状态
- 状态机与 AI 解耦：工作流状态只能由 harness 的 commands 推进，模型不能直接编辑 runtime/workflow_state.json
- 要求可核验依据：结论须指明数据出处（附件与行列）、公式编号或文献 ID，禁止无出处的断言
- 要求显式失败：信息不足时必须报告缺口并按失败类型路由，不允许编造数据或结论

**典型交互示例**

- 示例 1（题面解析）：输入：request/problem.md 全题面 + 附件结构说明。要求：拆解小问，输出 JSON 形式的题目理解、小问清单与全局符号表；对题面未给定的口径只能登记为待定假设，不得自行取值。模型输出经 harness 校验后写入 problems/<id>/problem_understanding.md。
- 示例 2（计算与核验）：输入：已接受的假设版本与公式版本、求解脚本、任务输出目录。要求：在隔离 task 中运行并给出约束残差、可行性结论和异常项；禁止修改假设或公式。结果由 sanity-checker 阶段独立复核，未通过则退回重做。

## 四、对 AI 输出的采纳、人工修改和核验情况

- 版本门禁：假设与公式的每个版本都需显式 ACCEPT/REJECT，模型不能自行放行
- 结构化校验：Agent 响应必须通过 JSON schema 校验，命令批次失败时整体回滚状态
- 计算隔离：计算在独立 task 与独立输出目录中运行，避免覆盖既有结果
- 独立复核：sanity-checker 对数量级、边界、约束残差和常识性做检查；引用与图表在论文校验阶段做双向闭合检查
- 人工审查：所有 AI 生成的假设、公式、代码、结果和论文文字均逐项人工复核，确认与题面、数据和实际运行结果一致后才进入下一阶段
- 不采用即丢弃：与数据、题面或运行结果冲突的 AI 输出一律退回重做，不得直接作为结论
- 语言润色只改表述，不改变技术内容与数值结果
